# Каталог «Лучшие из лучших»

## Сортировка и фильтры

Над каталогом находятся четыре независимых переключателя: пинг, доступность
YouTube, Telegram и AI. По умолчанию включены все четыре; можно выбрать любую
комбинацию, включая отсутствие критериев.

Сначала идут серверы с большим числом успешных проверок **включённых сервисов**.
Если включён пинг, при равенстве учитываются его доступность и меньшая задержка
HTTPS-запроса через прокси. Неизвестный пинг идёт перед подтверждённо неудачным.
Окончательный порядок при равенстве — по ID. Если все критерии выключены,
каталог упорядочен только по ID.

Кнопка **Плохой** вручную ставит сервер ниже всех неотмеченных, независимо от
сервисов и пинга. Повторное нажатие снимает отметку. Отметки привязаны к routing
`srv-v1` ref и сохраняются в этом браузере (`hr_best_of_best_bad_servers`).

Рейтинг учитывает результаты не старше шести часов: YouTube channel/thumbnail
contract 1, Telegram/AI/proxy ping contract 7. Старые и несовместимые результаты,
включая native YouTube playback, не считаются успешной проверкой превью.
В каждой строке отдельно показаны P, YT, TG и AI. Подсказки различают успешный,
отрицательный, неподтверждённый, пропущенный, устаревший и отсутствующий результат.

Два фильтра имеют разные назначения:

- **Скрыть непротестированные серверы** — включён по умолчанию. Сервер остаётся
  видимым, если хотя бы одна из отображаемых проверок действительно выполнялась
  (`attempts > 0`), независимо от её результата и выбранных критериев. Старые
  выполненные проверки тоже сохраняют видимость, но не повышают рейтинг.
- **Скрыть серверы, не прошедшие проверку** — выключен по умолчанию. Скрывает
  сервер при подтверждённом отрицательном результате хотя бы одного включённого
  критерия. Пропуск, неподтверждённость и устаревший результат не являются
  подтверждённым провалом. Если критерии выключены, этот фильтр никого не скрывает.

Выбранные члены пула обходят оба фильтра и остаются доступными для удаления.
Dead Servers всегда исключены из каталога, включая ранее выбранные. Сохранённые
мёртвые или отсутствующие участники учитываются в составе отдельно: кнопка
«Убрать из состава» явно удаляет их из черновика, применяемого при сохранении.
Поиск по имени или #ID продолжает ограничивать видимые строки, включая выбранные.
Счётчики показывают общее число членов пула и число видимых строк.

Переключатели сохраняются локально в браузере в `hr_best_of_best_catalog`.
Их изменение сразу перестраивает каталог. Галочки членства и порядок refs в пуле
сохраняются при сортировке, поиске, фильтрации и запоздалой загрузке; «Сохранить и
применить» отправляет полный выбор, а не только видимые строки.

Переключатель **Включить пул** меняет черновик; до нажатия «Сохранить и применить»
интерфейс явно показывает неприменённое изменение. Сохранённый состав выключенного
пула не означает его активацию. После успешного POST переключатель и статус берутся
из ответа применения; запоздалые GET не могут вернуть старое состояние. На время
применения переключатель, галочки состава и кнопка сохранения блокируются,
а слева отображается «Применение пула „Лучшие из лучших“…». При ошибке черновик
сохраняется для повторной попытки.

## Лимиты состава

С v1.3.33 пул имеет собственный лимит **16 участников**, независимый от лимита
**16 серверов фиксированных маршрутов** (правила, устройства и Torrent SOCKS).
Поэтому 16 участников пула можно включить
при уже существующих фиксированных маршрутах. Если один сервер используется в
обоих наборах, его Mihomo outbound не дублируется. Совокупный предел — 32 уникальных
дополнительных сервера. Паровозик удалён в v1.3.35.

## API

`GET /api/automation/best-of-best` дополняет каждую запись `candidates` полями:

```json
{
  "tested": true,
  "checks": {
    "youtube_thumbnails": { "state": "passed", "tested": true },
    "telegram": { "state": "failed", "tested": true },
    "ai": { "state": "unknown", "tested": true },
    "ping_proxy": { "state": "skipped", "tested": false }
  }
}
```

Допустимые состояния: `passed`, `failed`, `unknown`, `skipped`, `stale`,
`not-tested`. Поля `ref`, `passed` и `ping_ms` сохраняют прежний контракт.
`ref` остаётся routing `srv-v1`; сырые ссылки профиля и ошибки тестов в новый
контракт не включаются. Настройки каталога не записываются в router state.

Сортировка каталога не авторизует маршрутизацию: выбранному выходу по-прежнему
нужна отдельная свежая HTTPS-проверка runtime-пула. Число членов, sticky selection
и fail-closed поведение сохраняют существующие правила.

## Проверки локальной реализации

Покрыты все 16 комбинаций критериев, оба фильтра, отрицательные/неизвестные/
устаревшие/пропущенные результаты, сохранение выбора и порядка refs, запоздалая
загрузка, перезагрузка страницы и экран шириной 360 px. Backend проверяет
контракты, свежесть, привязку к текущему профилю и отсутствие приватных данных.

Исходная сортировка развёрнута в v1.3.31; результаты записаны
в [записи релиза](releases/v1.3.31.md). Исправления управления и ручные отметки
описаны в [записи v1.3.32](releases/v1.3.32.md).
