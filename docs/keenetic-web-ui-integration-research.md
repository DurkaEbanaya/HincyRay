# Keenetic Native Web UI Integration Research

Date: 2026-06-21
Router: Keenetic Giga KN-1012, KeeneticOS, kernel 4.9-ndm-5 aarch64

## 1. Filesystem Layout of the Keenetic Web UI

### Web UI Root
```
/usr/share/htdocs_/          # READ-ONLY (squashfs)
  index.html                 # Angular SPA entry point (<ndw-root>)
  main-JELMZ7TJ.js           # 6.2 MB minified Angular bundle (all routes, components, menu)
  polyfills-YL6PNVIW.js      # Angular polyfills
  styles-DKYWR66I.css        # Compiled styles (71 KB)
  worker-G5Z4KKB2.js         # Service worker
  prerendered-routes.json    # {"routes": {}} (empty - no prerendering)
  ndmComponents.js -> /var/run/ndmComponents.js       (symlink, writable)
  ndmConstants.js -> /usr/share/htdocs_/assets/ndmConstants.js
  ndmConstants.json -> /usr/share/htdocs_/assets/ndmConstants.json
  ndmContacts.js -> /var/run/ndmContacts.js
  ndmContacts.json -> /var/run/ndmContacts.json
  ndmFeatures.json -> /var/run/ndmFeatures.json
  ndmLanguages.json
  version.js -> /var/run/version.js
  assets/
    db/  fonts/  images/  language/  sprite/  system-modes-icons/
    ndmConstants.js  ndmConstants.json
  wizards/                   # Separate Angular app for setup wizards
    index.html  main-*.js  polyfills-*.js  styles-*.css
```

### Framework
- **Angular SPA** (Angular 17+, Ivy compiler, esbuild output)
- Custom element: `<ndw-root>` (NDM Web)
- Component prefix: `ndw-*` (e.g. `ndw-application-card`, `ndw-button`, `ndw-access-point-settings`)
- ~200+ Angular components in the bundle
- Routes use Angular Router with lazy loading
- Only one "app" route exists: `app/transmission` (for the Transmission BitTorrent client)

### Component Registry (`ndmComponents.js`)
Located at `/var/run/ndmComponents.js` (writable tmpfs, 1341 bytes):
```javascript
window.NDM.profile.components = {
  "base": true,
  "cloudcontrol": true,
  "dhcpd": true,
  "dns-filter": true,
  "opkg": true,
  "ssh": true,
  // ... ~45 built-in KeeneticOS components
};
window.NDM.profile.features = { "wifi6": true, "wpa3": true, ... };
window.NDM.model = "Giga";
window.NDM.mode = "router";
```
- Generated by NDM (`/bin/ndm`) at boot from installed KeeneticOS packages
- The Angular app calls `isComponentInstalled(componentName)` to show/hide menu items
- Components are **server-controlled** — installed via Keenetic cloud (my.keenetic.net)
- Cannot be added locally (confirmed by Keenetic Ported wiki: "Components are not modifiable, requested from the server")

### Nginx Configuration
- **Binary**: `/usr/sbin/nginx` (KeeneticOS built-in)
- **Config**: `/tmp/nginx/nginx.conf` (dynamically generated by `/bin/ndmf`, 65 KB)
- **Listen ports**:
  - `192.168.1.1:80` — HTTP, redirects to HTTPS (`my.keenetic.net` domain)
  - `192.168.1.1:5083` — HTTPS (main web UI, TLS 1.2/1.3)
  - `127.0.0.1:79` — RCI (local only, no auth)
  - `127.0.0.1:78` — "transmission only" stub
- **Key locations** (in the HTTPS server block on port 5083):
  - `location /` — serves static files from `/usr/share/htdocs_`, `try_files $uri @ndm`
  - `location @ndm` — SCGI proxy to NDM (SPA fallback for client-side routes)
  - `location /rci` and `~* ^(/ci$|/.*))|(/rci/.*)` — RCI (Remote Control Interface), SCGI to NDM
  - `location ~* ^/fui(.*)$` — "Foreign UI" authenticated RCI endpoint (SCGI to NDM, not a web proxy)
  - `location /wizards/` — setup wizard app
  - `location ~* ^/storage/(.*)` — file browser (`alias /tmp/mnt/$1`)
  - `location ~* ^/download/(?<path>.*)` — file downloads
  - `location = /ndmComponents.js` — returns 404 in some server blocks (prevent direct access)
- **Security headers** (applied to most locations):
  ```
  X-Frame-Options: DENY
  Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-eval' 'unsafe-hashes' 'unsafe-inline'; connect-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline' 'unsafe-eval' 'unsafe-hashes'; base-uri 'self'; form-action 'self';
  ```

### Filesystem Permissions
| Path | FS Type | Writable | Persistence |
|------|---------|----------|-------------|
| `/` (root) | squashfs | **READ-ONLY** | Survives reboot |
| `/usr/share/htdocs_/` | squashfs | **READ-ONLY** | Survives reboot |
| `/etc/nginx/` | squashfs | **READ-ONLY** | Survives reboot |
| `/tmp/` | tmpfs (RAM) | Writable | **Lost on reboot** |
| `/tmp/nginx/` | tmpfs (RAM) | Writable | **Lost on reboot** |
| `/var/run/` → `/tmp/run/` | tmpfs (RAM) | Writable | **Lost on reboot** |
| `/opt/` (Entware) | ext4 (USB/internal) | Writable | Survives reboot |

### NDM Binaries
- `/bin/ndm` — NDM daemon (main router management process)
- `/bin/ndmc` — NDM CLI (interactive shell, needs terminal)
- `/bin/ndmf` — NDM framework (19 KB, generates nginx config, dhcp configs, etc.)
- `ndmq` — NOT installed on this router (can be compiled from github.com/ndmsystems/ndmq)

## 2. Can Third-Party Apps Register Menu Items?

**No.** There is no plugin/extension/component registration mechanism for third-party apps.

The menu system works as follows:
1. NDM generates `ndmComponents.js` from installed KeeneticOS packages (cloud-controlled)
2. The Angular app reads `window.NDM.profile.components` at startup
3. Menu items are **hardcoded in the 6.2 MB minified Angular bundle** — each component has a corresponding route, label, and icon baked into the compiled TypeScript
4. The `MenuService` class calls `queryMenuData()` which polls the RCI for dynamic data, but the available menu sections are fixed by the component list
5. Adding a component name to `ndmComponents.js` without a corresponding route in the Angular bundle would produce nothing — the app would check `isComponentInstalled("myapp")` and find no route to navigate to

The component enum in the Angular bundle includes:
```javascript
t.TRANSMISSION="transmission", t.TSMB="tsmb", t.UDPXY="udpxy",
t.USB="usb", t.WEBDAV="webdav", t.WIREGUARD="wireguard", ...
```
All are KeeneticOS built-in packages. There is no `t.CUSTOM` or plugin slot.

## 3. Known Methods Others Have Used

### Transmission (Built-in KeeneticOS Component)
- The only "embedded" third-party-style app in the Keenetic UI
- Angular route: `app/transmission`
- When clicked, the Angular app redirects: `location.href = ${location.origin}/transmission/web/?lang=...`
- Nginx proxies `/transmission/` to the Transmission daemon's built-in web UI
- Only works when the `transmission` component is installed from Keenetic's cloud
- Port 78 is labeled "transmission only" in nginx config

### nfqws-keenetic-web (251 stars, github.com/nfqws/nfqws-keenetic-web)
- Anti-DPI tool with a PHP web interface
- **Standalone web server on port 90** (`http://192.168.1.1:90`)
- Uses Entware's `php` and a built-in web server
- Authentication: Entware root/keenetic credentials
- **No integration with the native Keenetic UI** — completely separate

### xkeen-keenetic-web (github.com/johnroger67/xkeen-keenetic-web)
- XKeen (DPI bypass) configuration UI, based on nfqws-keenetic-web
- **Standalone web server on port 91** (`http://192.168.1.1:91`)
- Same approach: PHP, Entware, own authentication
- **No integration with the native Keenetic UI**

### AdGuard Home on Keenetic
- Runs as an Entware package with its own web UI on a custom port (typically 3000)
- **No integration with the native Keenetic UI**

### Community Consensus
The Keenetic modding community (forum.keenetic.com, forum.keenetic.ru, 4pda.to, keeneticported.dev) uniformly uses **separate-port standalone web servers** for third-party apps. No one has successfully added a native menu item to the Keenetic web UI.

## 4. Feasibility Assessment

### Native Menu Item in Keenetic UI: **IMPOSSIBLE** (without extremely fragile hacks)

**Reasons:**
1. Root filesystem is **read-only squashfs** — cannot modify `index.html`, the Angular bundle, or any static file
2. Component registry is **server-controlled** — components are installed from Keenetic's cloud, not locally
3. Menu items are **compiled into the 6.2 MB minified Angular bundle** — there is no runtime menu configuration
4. No plugin/extension API exists in the Angular app
5. `X-Frame-Options: DENY` and `CSP: default-src 'self'` prevent embedding external content

### Hackish Approaches (Not Recommended)

#### Option A: Inject JS via `ndmComponents.js` + Nginx Reverse Proxy
**Feasibility: Hard / Fragile**

1. Modify `/var/run/ndmComponents.js` to append JavaScript that:
   - Waits for Angular to bootstrap
   - Uses `MutationObserver` or `setInterval` to find the navigation menu DOM
   - Injects a `<a>` or `<button>` element that links to `/hincyray/`
2. Modify `/tmp/nginx/nginx.conf` to add a reverse proxy location:
   ```nginx
   location /hincyray/ {
     proxy_pass http://127.0.0.1:8088/;
     proxy_set_header Host $host;
     proxy_set_header X-Real-IP $remote_addr;
   }
   ```
3. Reload nginx: `nginx -s reload`
4. Run a watchdog script from `/opt/etc/init.d/` that re-applies both changes whenever NDM regenerates them

**Problems:**
- Angular's DOM structure is minified and changes between firmware versions
- NDM regenerates `ndmComponents.js` and `nginx.conf` on config changes, reboots, and firmware updates
- The injected menu item would disappear on any NDM config reload
- CSP `connect-src 'self'` would block HincyRay's API calls unless proxied through nginx
- Would break on every firmware update
- No authentication passthrough — HincyRay would need its own auth or bypass

#### Option B: Modify Nginx Config Only (Reverse Proxy, No Menu Item)
**Feasibility: Moderate**

1. Add a reverse proxy location to `/tmp/nginx/nginx.conf`
2. Access HincyRay at `https://192.168.1.1:5083/hincyray/` (same origin as Keenetic UI)
3. Watchdog re-applies after NDM regenerates config

**Advantages over separate port:**
- Same origin as Keenetic UI (no CORS issues)
- Uses Keenetic's TLS certificate
- Could potentially share authentication if RCI auth headers are passed through

**Problems:**
- Still no menu item in the Keenetic UI
- Config is lost on NDM reload/reboot without a watchdog
- The `default-src 'self'` CSP would need to be relaxed for HincyRay's inline styles/scripts

## 5. Recommended Technical Approach

### Primary: Keep HincyRay on Port 8088 (Current Approach)

This is what every other third-party Keenetic app does. It works, it's stable, and it doesn't break on firmware updates.

**Enhancements to consider:**
1. Add a bookmark/shortcut URL on the HincyRay web panel page: `http://192.168.1.1:8088/`
2. Add a QR code for mobile access
3. Consider adding optional Entware nginx reverse proxy for HTTPS access:
   ```
   opkg install nginx
   # Configure /opt/etc/nginx/nginx.conf to proxy :8088 -> :443 with self-signed cert
   ```

### Secondary: Nginx Reverse Proxy via Config Patching (If Same-Origin Access Is Needed)

If there's a strong reason to have HincyRay on the same origin as the Keenetic UI (e.g., to avoid mixed-content warnings, to share TLS cert), a watchdog approach can work:

```
/opt/etc/init.d/S98nginx-patch
```

This script would:
1. Wait for nginx to start
2. Check if `/tmp/nginx/nginx.conf` contains `hincyray` — if not, patch it:
   - Insert `location /hincyray/ { proxy_pass http://127.0.0.1:8088/; ... }` before the final `}` of the main HTTPS server block
3. Reload nginx
4. Monitor for config regeneration (compare mtime of `/tmp/nginx/nginx.conf`) and re-patch as needed

**Caveat:** This approach requires maintaining the watchdog script across firmware updates. The nginx config structure may change between KeeneticOS versions.

### Tertiary: JS Injection via ndmComponents.js (If a Menu Item Is Absolutely Required)

This is the only way to get a native-looking menu item, but it is extremely fragile:

1. Append to `/var/run/ndmComponents.js`:
   ```javascript
   // Inject HincyRay menu item into Keenetic UI
   (function() {
     function addMenuItem() {
       var nav = document.querySelector('ndw-navigation-menu, .navigation-menu, [class*="menu"]');
       if (!nav) { setTimeout(addMenuItem, 500); return; }
       // Find a suitable parent element and inject a link
       var item = document.createElement('a');
       item.href = '/hincyray/';
       item.target = '_blank';
       item.textContent = 'HincyRay VPN';
       // Styling to match Keenetic UI...
       nav.appendChild(item);
     }
     document.addEventListener('DOMContentLoaded', addMenuItem);
   })();
   ```
2. Add nginx reverse proxy for `/hincyray/` (see Secondary approach)
3. Watchdog to re-apply both changes

**Warning:** This will break on every KeeneticOS firmware update. The Angular DOM structure is minified and undocumented. The injected element will not match the Keenetic UI styling without significant effort.

## 6. Summary

| Approach | Native Menu Item | Stability | Effort | Recommended |
|----------|-----------------|-----------|--------|-------------|
| Separate port (current) | No | High | None | Yes |
| Entware nginx reverse proxy | No | High | Low | Maybe |
| KeeneticOS nginx config patching | No | Medium | Medium | If same-origin needed |
| JS injection + nginx patching | Yes (fragile) | Low | High | No |
| Wait for Keenetic to add plugin API | Yes | High | None (but unlikely) | Long-term hope |

**Bottom line:** Keenetic's web UI is a closed Angular SPA on a read-only filesystem with no plugin system. Every third-party app in the Keenetic ecosystem runs on a separate port. HincyRay's current approach (port 8088) is the correct and standard one.
