# HincyRay v1.2.2

v1.2.2 fixes benchmark controls, hardens YouTube service diagnostics, and makes active-profile switches take effect for existing traffic.

## Release scope

- The server-concurrency field is again a native accessible selector with the supported 1–6 range; it is no longer converted into a custom menu clipped by the test-settings panel.
- Quick and Full Test use the same serialized YouTube playback implementation whenever the temporary Mihomo runtime starts. Quick no longer reports YouTube as skipped merely because unrelated ICMP, direct TCP, and generic proxy ping diagnostics all failed.
- The YouTube transaction retries one transient DNS/connect/TLS/reset/timeout or HTTP `408`/`425`/`429`/`5xx` failure with fresh visitor state. Bootstrap and player HTTP statuses are validated, and the player response is bounded to 2 MiB.
- Media validation tries up to three distinct direct video formats, preserving a progressive fallback. Live diagnostics proved that `itag 160` returned CDN `403` while other direct formats from the same player response delivered the bounded media range.
- After a successful active-profile transaction, HincyRay closes existing Mihomo connections. Manual switches and verified automatic failover therefore force applications to reconnect through the newly selected upstream instead of retaining the old exit IP.
- Connection closure is a best-effort post-commit effect: config/runtime/state rollback semantics remain unchanged, and failure to close connections does not roll back a successfully applied profile.
