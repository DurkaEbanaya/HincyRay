# HincyRay v1.3.8

Date: `2026-09-16`.

The hash-verified local router update is deployed and verified. GitHub publication remains pending; no v1.3.8 GitHub asset availability is claimed.

Historical v1.3.7 artifact SHA256, actual gate counts, and live deployment evidence remain unchanged in [`v1.3.7.md`](v1.3.7.md). They are not v1.3.8 evidence.

## Update scope

- Unified global, selected, subscription, group, and single-profile actions share browser-stored parameters and one start flow.
- `complete_scope` uses all native services with either YouTube/Telegram failure short-circuiting (existing Quick internally) or continued checking (existing Full internally). Shared actions disable download/upload speed stages.
- `find_n` retains targets 1-20 and supported YouTube, YouTube+Telegram, or YouTube+Telegram+AI Studio prefixes. Prefix-only complete-scope checking and an independent continue-after-failure discovery policy are not offered.
- Explicit single/bulk Dead Servers diagnostics use complete scope even when browser preferences select find N. Discovery excludes dead candidates, never changes active identity, and never runs profile post-actions. Completed, non-cancelled complete-scope tests retain existing opt-in Quick/Full post-action rules.
- Discovery keeps fresh-history ordering only, canonical lifecycle deduplication, endpoint/provenance diversification, real-protocol preflight, and requested-prefix semantics. Preflight rejection is not persisted health failure or Dead Servers evidence.
- Scheduler workers wait for temporarily saturated target slots instead of permanently retiring. Failed/rejected candidates release slots so waiting workers can resume; target completion, exhaustion, and cancellation remain distinct.
- Status explains requested workers, effective capacity, active work, admission limits, and `memory_cap`, `candidate_count`, and `target_slots` reasons.
- Temporary-core startup estimates an 80 MiB router reserve and 48 MiB per worker. Unknown memory budgets or known budgets permitting zero workers return HTTP 503 instead of forcing one worker.
- The memory guard is a startup admission estimate, not a continuous reserve guarantee. Native YouTube and Telegram probes remain serialized; four requested workers do not imply four simultaneous YouTube checks. Cancellation still interrupts and reaps owned children.
- Existing adaptive/security/status-redaction/navigation-focus feature edits are retained.

Usage and API mapping: [`../adaptive-discovery.md`](../adaptive-discovery.md). Historical notes: [`../../CHANGELOG.md`](../../CHANGELOG.md).
