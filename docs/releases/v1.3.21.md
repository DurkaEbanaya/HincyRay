# HincyRay v1.3.21

Date: `2026-09-23`.

Torrent SOCKS5 traffic is identified by the Mihomo inbound `torrent-socks-in`, not by its destination or currently selected proxy. Both the active-connections list and grouped connection table display the Torrent SOCKS5 label; a group with mixed traffic shows how many connections came through that inbound.

Mihomo assigns each established connection a route at creation time. A successful routing config reload does not reroute already established TCP/UDP sessions. After a Torrent SOCKS5 target or listener change is successfully activated with a running core, HincyRay reads a bounded Mihomo snapshot and closes only matching inbound connection IDs (at most 128 IDs and a 10-second deadline). Applying changed general routing settings/rules or explicitly applying/resetting routing, presets, or device routes closes current Mihomo connections to force subsequent connections to evaluate the new policy. Save-only calls and failed activations do not close connections. Existing flows are interrupted and the client must reconnect; closure is not a guarantee that the remote endpoint or torrent peer will retry. A separate `reconnect` response records the scope/completion and the Web UI warns on partial failure without undoing a successfully applied policy.
