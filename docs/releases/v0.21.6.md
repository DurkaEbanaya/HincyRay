# HincyRay v0.21.6

v0.21.6 introduces a first-class Dead Servers lifecycle contract instead of encoding lifecycle state into mutable profile groups or numeric IDs.

## Lifecycle and identity contracts

- `Profile.group` remains subscription/manual provenance. Dead Servers is a virtual projection backed by lifecycle membership.
- Current profiles use opaque `srv-v2` lifecycle references across Dead Servers, Deep Bench, selectors, and quality history.
- Routing remains a separate `srv-v1` contract backed by `server_route_registry`; lifecycle v2 references cannot be parsed as routing targets.
- Lifecycle canonicalization removes display fragments, normalizes URL scheme and domain-host case, orders query keys deterministically, preserves repeated query values, and canonicalizes VMess JSON without `ps`.
- Startup migration converts raw and resolvable current-profile v1 lifecycle state to v2. Legacy orphan v1 Trash entries remain restorable.

## State and dataplane safety

- Batch move/restore validates the complete request before mutation; moving the active profile returns HTTP 409.
- Dead profiles are excluded from normal, all, subscription, automatic, and Deep Bench automatic scopes. Explicit diagnostic requests may still address them.
- A dead profile cannot be activated. Startup reconciles contradictory legacy state by removing the active profile from Dead Servers.
- Enabled server-pinned routes preserve user intent, use the active fallback while their target is dead, and recover after restore.
- Manual and automatic lifecycle transitions share one serialized transaction boundary. Persist or Mihomo activation failure rolls lifecycle fields back without erasing unrelated concurrent state changes.

## Web UI

- Added the virtual Dead Servers group with selection, bulk move/restore, provenance, and lifecycle-aware benchmark/history projections.
- Frontend contract coverage verifies the UI/API boundary and prevents routing/lifecycle identity crossover.
- Desktop egui stroke widths are explicitly typed as `f32`, satisfying the stable compiler's `float_literal_f32_fallback` lint in the all-features CI profile without changing rendering values.
- The local subscription HTTP fixture now consumes bounded request headers before replying, so Linux and macOS both verify the intended HTTP-200 content error rather than an OS-dependent TCP reset.
