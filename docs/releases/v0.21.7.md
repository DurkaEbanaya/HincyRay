# HincyRay v0.21.7

v0.21.7 removes two avoidable wait/failure paths: DIRECT routing no longer depends on VPN-backed DNS resolution, and operators can quickly screen many servers without running the full sequential benchmark.

## DIRECT routing resilience

- Mihomo `DIRECT` outbounds use `DnsSettings.local_servers` as `direct-nameserver` by default.
- Explicit advanced `mihomo_features.dns_direct_nameserver` values still override the defaults.
- DIRECT/RU routing rules remain unchanged; only the resolver selected by the DIRECT outbound is corrected.
- Live generated config uses `77.88.8.8` and `8.8.8.8` for `direct-nameserver`.

## Quick Test

- The profile bulk-action bar includes **Quick Test** for selected profiles.
- Quick Test makes one TCP connection probe per profile with a one-second timeout.
- Up to eight profiles run concurrently. The job remains bounded and cancellable through the existing benchmark runtime.
- Quick Test skips download, upload, protocol startup, and temporary Mihomo processes. Full TCP/HEAD/GET benchmarks remain unchanged for quality and protocol verification.
- A live three-profile Quick Test completed all three profiles in one second.

## Connection continuity and Web UI

- Background auto-VPN learning persists learned exceptions without restarting Mihomo. Changes enter the dataplane on the next explicit routing apply or core restart.
- Existing auto-VPN exceptions and routing priority are preserved.
- Both Web UI auto-switch controls now reflect the same backend value after either settings view loads.
- The Web UI explains the deferred auto-VPN application contract.
