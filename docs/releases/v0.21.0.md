# HincyRay v0.21.0

HincyRay v0.21.0 is the hardening and operability release. It converts the router daemon into a contract-driven control plane with explicit auth/security boundaries, typed bounded APIs, transactional runtime activation, browser smoke coverage, safer installer lifecycle semantics, and verified Keenetic deployment.

## Highlights

- Argon2id Web UI password storage with legacy plaintext migration.
- Cryptographically secure bounded sessions with expiry, caps, throttling, and invalidation.
- Same-origin mutation checks, bounded request bodies, security headers, and `sessionStorage` Bearer handling.
- Backend redaction for generated Mihomo YAML, including preview output.
- Versioned API contracts, onboarding readiness, routing preview/explain/context, factual memory reporting, safe mode, and paginated Mihomo connections.
- Transactional apply path with readiness observation and rollback of config/core/firewall/policy state.
- Responsive Web UI improvements, exact flag+host connection search, route explanation, apply preview, safe-mode/readiness cards, and prompt-free rename dialog.
- Safer Entware installer/init lifecycle with authoritative PID identity checks and no argv-based process killing.
- Deterministic browser smoke tests and CI coverage for installer lifecycle, frontend/backend contracts, Rust gates, and browser behavior.
- Live Keenetic validation of the release artifact.

## Security and authentication

v0.21.0 replaces the old Web UI auth boundary with a durable security model:

- Passwords are persisted only as Argon2id PHC hashes with random salts.
- Existing plaintext password state is migrated on load and not serialized again.
- Session tokens are 256-bit cryptographically random Bearer tokens.
- Sessions expire by idle timeout and absolute lifetime, and the daemon caps concurrent sessions.
- Login failures are throttled per source IP.
- Changing username, password, auth-enabled state, or restoring state invalidates sessions.
- State-changing requests reject mismatched `Origin`/`Host` when `Origin` is present.
- Request bodies are bounded and invalid UTF-8/length cases fail before handler logic.
- The Web UI stores the Bearer token in `sessionStorage`; stale `localStorage.hincyray_token` is removed during boot.
- Password hashing/verification capacity is limited per daemon instance, avoiding CPU exhaustion while keeping independent tests isolated.

## Secret redaction

Generated Mihomo YAML is no longer treated as safe text just because HincyRay produced it:

- `GET /api/mihomo-config` and `GET /api/mihomo-config/preview` redact before returning config to the browser.
- Redaction covers known credential families: passwords, private keys, preshared keys, API/bearer secrets, client TLS key material, provider URLs with opaque tokens, and related fields.
- Redaction is fail-closed for malformed generated YAML.
- The Web UI escapes rendered config instead of injecting it as HTML.

## Typed, bounded API contracts

New module: `src/hincyray_api.rs`.

New and hardened API contracts include:

- `GET /api/contracts` — contract version, bounded endpoint list, same-origin policy, and auth scheme.
- `GET /api/onboarding/status` — readiness checks and remediation for Mihomo, active profile, GeoIP asset, core, transparent firewall/TPROXY, and ndm hook.
- `GET /api/routing/summary` — compact transparent-routing, safe-mode, rule, device-route, conflict, and GeoBase apply state.
- `GET /api/routing/connection-context` — bounded server projection for connection routing controls without raw share links or credentials.
- `GET /api/routing/preview` — desired vs applied config hashes, GeoBase generations, restart/firewall effects, changes, and conflicts without mutating runtime.
- `POST /api/routing/explain` — local route explanation for host/resource/source/port/network with Mihomo-owned rule domains identified as runtime-owned.
- `GET /api/memory-estimate` — factual current-state report: rule-source bytes on disk, current Mihomo RSS, MemAvailable, counts, safe-mode state, and observed risk.
- `GET/POST /api/safe-mode` — reversible suppression of heavy optional features without deleting durable user data.
- `POST /api/mihomo-api/connections/page` — server-side search, filtering, offset, and clamped limit for Mihomo connections.
- `POST /api/mihomo-api/connections/device-traffic` — bounded per-device observed traffic accounting.

## Transactional runtime activation

Routing/config apply now follows a serialized transactional path:

1. Clone authoritative state and select desired/applied GeoBase projection.
2. Generate and validate Mihomo YAML.
3. Save previous config bytes and atomically write the candidate.
4. Restart/start Mihomo and observe process plus External Controller readiness.
5. Apply firewall state when requested.
6. Commit desired GeoBase generation only after successful activation.
7. Restore previous config, core state, firewall state, and policy state on failure.

This makes apply failures recoverable instead of leaving mixed desired/applied state.

## Safe mode

Safe mode is now a reversible runtime policy. It can suppress heavy generated features such as RKN bypass, managed GeoBases, proxy/rule providers, sub-rules, raw/typed rules, tunnels, and smux. It does not purge profiles, subscriptions, source artifacts, backups, or history.

## Web UI

The Web UI remains a single embedded HTML document with no CDN or frontend build step, but its behavior is now more bounded and testable:

- Connections views use paginated server-side search instead of unbounded browser-side dumps.
- Search includes the exact rendered flag+host label, fixing queries such as `🇷🇺 chatgpt.com`.
- Connection route controls use bounded server context and canonical actions.
- Readiness/onboarding, route explanation, apply preview, factual memory, and safe-mode cards were added.
- Profile rename uses an in-page dialog with keyboard Enter/Escape behavior instead of `window.prompt`.
- Responsive table-to-card behavior adds `data-label` from table headers for mobile/tablet layouts.
- Mobile/tablet navigation and sheets were added.
- Static frontend contract tests now verify new boot and API expectations.

## Module boundaries

- `hincyray_security` owns password hashing, verification, sessions, login throttling, and password-work limiting.
- `hincyray_api` owns typed DTOs and bounded API contracts.
- `hincyray_webui` owns the embedded Web UI asset boundary.
- `hincyray` remains the composition root for HTTP dispatch, persisted state, activation, core/firewall/watchdog orchestration, and route handlers.

## Installer and lifecycle safety

The installer/init path was hardened after real SSH lifecycle testing:

- Generated init scripts detach with `nohup` and redirect stdin.
- The authoritative PID file is owned by the init script.
- `/proc/<pid>/exe` is checked before signaling a process.
- Stale PID files pointing at a foreign process are rejected.
- Lifecycle operations are guarded by a lock and rollback path.
- The installer uses daemon API startup where appropriate.
- Operational docs now forbid `pgrep -f`, `pkill -f`, `killall`, and process-name lifecycle scans for HincyRay, because they can match the invoking SSH command and terminate their own shell.

## Upgrade notes

- Existing plaintext Web UI passwords migrate to Argon2id on state load.
- Existing browser auth tokens are invalidated by the new session model; log in again if Web UI auth is enabled.
- Do not manage the daemon with process-name scans. Use `/opt/etc/init.d/S99hincyray start|stop|restart|status`.
- The compatibility endpoint named `/api/memory-estimate` now reports observed current-state facts rather than speculative future allocation.
