# HincyRay v0.21.5

v0.21.5 replaces score-only profile failover with fresh protocol verification and immutable profile identity.

## Fixed contract

- Historical quality scores order failover candidates but never prove current availability.
- Every candidate is tested through a temporary Mihomo instance using three HTTPS requests; any packet loss rejects the candidate.
- Failed active profiles and rejected candidates receive persisted cooldowns keyed by the raw share link.
- Trash Bin profiles, cooldown profiles, and already rejected raw links are excluded.
- Numeric profile IDs do not cross the verification boundary. The winning raw link is resolved against current state immediately before transactional activation.
- A concurrent user switch or subscription refresh aborts the stale failover attempt.
- Each recovery cycle checks at most eight candidates, bounding process and network work while Mihomo's DIRECT fallback remains available.

## Incident evidence

- Router daemon, Mihomo process, listeners, firewall, DNS, memory, load, and I/O remained healthy during the reported instability.
- The selected upstream remained `alive=false` while Mihomo correctly routed the fallback group to `DIRECT`; direct-accessible resources worked while VPN-required traffic timed out.
- Corrected protocol benchmarks showed that several low-TCP-latency profiles had 33-100% HTTPS loss. The replacement profile passed 18/18 real HTTPS requests and remained `proxy-active` during extended native observation.
- Existing score-only auto-switch remained disabled until this contract was replaced because stale EWMA still ranked a known-dead profile above the verified replacement.
