# HincyRay v0.22.0

v0.22.0 replaces proxy-port and CDN smoke signals with bounded end-to-end YouTube and Telegram validation, while removing obsolete high-memory routing inputs.

## Native service Quick Test

- Quick Test runs selected profiles sequentially through one temporary Mihomo SOCKS listener per profile.
- YouTube bootstraps visitor state, calls the narrow `ANDROID_VR` Innertube player contract, selects a direct video format, and downloads a 512 KiB media range through the tested profile.
- The final YouTube path is Rust + `curl`; it has no Python, `yt-dlp`, QuickJS, EJS, Node, TUN, or tun2socks dependency.
- Telegram uses an authorized `grammers` client to resolve one configured public peer, load one configured message, and download one 256 KiB media chunk through the tested profile.
- Persisted `resource_tests` use contract version 4. The Web UI ignores obsolete CDN, unauthenticated handshake, and intermediate extractor results.

## Telegram provisioning and secret isolation

- Added `GET /api/telegram-probe/status`.
- Added `POST /api/telegram-probe/request-code`.
- Added `POST /api/telegram-probe/confirm`, including optional Telegram 2FA.
- Added `POST /api/telegram-probe/delete`, which attempts sign-out and removes local files.
- Telegram API hash, phone, login code, and 2FA password are never returned by the API and never stored in `state.json` or browser storage.
- `telegram-probe.json`, `telegram.session`, and SQLite sidecars are private mode `0600`.
- Quick Test is sequential because one session must not be opened concurrently by multiple clients.

## Web UI

- Added compact versioned `YT` and `TG` status pills to profile and favorites rows.
- Added a persisted gear menu for optional profile metric columns.
- Added Telegram setup/status/confirm/delete controls under testing settings.
- Browser smoke verifies service pills, metric persistence, provisioning payloads, and removal of transient credentials from fields/browser storage.

## Routing and geo assets

- Removed the oversized legacy RKN bypass state, API, Web UI, rule-provider generation, refresh path, and installer handling.
- Removed the router `geoip.dat` path. Supported runtime assets are MetaCubeX `geosite.dat` and `geoip.metadb`.
- Under `MATCH,proxy`, managed GeoBase keeps automatically classified Active entries in its manifest without loading a redundant Active provider; static Active networks remain explicit.
- Renamed the IP-based preset to **RU IP Direct (advanced)** to distinguish it from GeoSite RU Direct.
- Consolidated current routing controls around RU Direct, managed GeoBase, and bounded Always VPN exceptions.
