# HincyRay v1.3.17

Date: `2026-09-22`.

This release adds a dedicated authenticated Torrent SOCKS5 identity without pretending that router-side DPI can reliably recognize encrypted BitTorrent traffic. GitHub commit, push, and release remain pending and unauthorized.

## Contract

- The feature adds one optional SOCKS5 listener to the existing Mihomo process; it does not run a second proxy core or VPN instance.
- A torrent client explicitly configured for this listener supplies the application identity. Listener-level routing supports DIRECT, canonical active VPN, REJECT, Parovozik, and fixed-server targets.
- TCP and SOCKS5 UDP are enabled. Peer, tracker, and DNS proxying plus direct-fallback prevention are client responsibilities. DHT/uTP coverage depends on the client's SOCKS5 UDP support.
- The listener is disabled by default. Enabling requires Web UI authentication, a literal loopback/private IPv4 address, a non-colliding port, a username, and a 12-512 byte password.
- Fixed targets retain the existing fail-closed server-group semantics: unavailable fixed server falls back to the canonical active VPN, and no VPN target falls through to WAN.

## Safety

- The routing API returns `password_set`, never the password. Generated-config responses redact listener users, request and persisted structs redact credentials from `Debug`, and preview/browser fixtures remove submitted secrets after use.
- State, generated Mihomo config, validator input, corrupt-state copies, and local backups use explicit Unix mode `0600`. WebDAV state transfer requires HTTPS and disables redirects.
- Fixed torrent targets participate in route-registry retention, identity migration, pinned observation, profile/group/subscription deletion and refresh protection, and Dead Servers dataplane decisions.
- Settings apply and local/WebDAV restore validate complete candidate state before persistence and roll back state, config, core, firewall, selector, and exact TCP/UDP socket contracts on failure.
- Enabling the listener does not alter normal SOCKS sniffing or QUIC behavior when transparent routing is disabled.
