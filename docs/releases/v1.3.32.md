# v1.3.32 · 2026-09-28

Best-of-best pool UI now uses the successful application response as its source
of enabled state, ignores obsolete GET responses, blocks membership/enable edits
during apply, and distinguishes an unapplied draft, a saved disabled pool, and an
enabled pool. The shared operation-instance sidebar scanner and pending button
indicate application, including failure cleanup.

Dead Servers are excluded by the catalog API and defensively by the browser.
Previously saved dead/missing members remain counted separately and can be
explicitly removed from the draft. Manual reversible “bad” marks demote servers
below normal catalog entries and persist per routing ref in browser-local storage.
Details: [catalog behavior](../best-of-best-catalog.md).
