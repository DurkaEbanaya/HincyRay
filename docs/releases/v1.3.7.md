# HincyRay v1.3.7

Date: `2026-09-16`.

The hash-verified local artifact is deployed on the Keenetic router. GitHub publication is pending.

## Release scope

- Adaptive Find Servers targets 1-20 unique lifecycle identities across all live profiles, a selection, or one subscription. Required service prefixes are YouTube, YouTube+Telegram, and YouTube+Telegram+AI Studio; Telegram requires the existing authorized session.
- Current-contract service history younger than six hours affects order only. Every counted server passes a fresh measurement; canonical aliases count once, endpoint/provenance buckets are interleaved, and rotating exploration broadens coverage of unknown candidates.
- Bounded real-protocol HTTPS preflight uses isolated temporary Mihomo cores and reuses successful cores for requested native probes. Preflight rejects skip media work and are not persisted health failures or Dead Servers evidence.
- Target completion stops candidate admission within router memory/concurrency bounds. Exhaustion and cancellation are distinct outcomes; cancellation interrupts and reaps benchmark-owned children. Partial requested-prefix success is not exhaustive Quick success.
- Discovery never changes the active server or runs Quick/Full promotion/dead-movement post-actions; the serving core, routing, DNS, and firewall remain unchanged.
- Login-throttle overflow preserves existing blocks. Unavailable or malformed local controller observations reset the failure streak without active-profile health penalties or failover; the canonical Mihomo fallback group remains the health authority.
- Benchmark status omits raw connection credentials, redacts diagnostic strings, safely remaps results to current profile IDs, and excludes unresolved identities. Delayed navigation focus cannot steal focus from an input on the next animation frame.

Usage, API semantics, and limitations: [`../adaptive-discovery.md`](../adaptive-discovery.md). Historical changes remain in [`../../CHANGELOG.md`](../../CHANGELOG.md).
