# HincyRay v1.3.5

v1.3.5 bounds router control-plane memory, threads, logs, and child-process lifetimes after a live thread-exhaustion failure.

## Release scope

- HTTP serving is limited to 32 fallible workers with 512 KiB stacks. Request lines, individual and aggregate headers, header counts, and simultaneous large bodies are bounded before unauthenticated clients can consume router memory or exhaust OS threads.
- Active Mihomo logs are capped during runtime, `/api/logs` reads only a bounded tail, and generation tracking preserves log consumers across in-place truncation and rapid regrowth.
- Speed-test, WebDAV, Mihomo controller, GitHub API, and asset responses are streamed or size-capped. Memory-heavy backup operations are serialized and detached DNS resolution is limited to eight workers.
- Status and routing responses omit internal probe caches, periodic status polling no longer replaces the routing form, and live Parovozik metadata is pruned to its configured budget.
- Deep Bench accepts only a 1-15 minute stability window, bounds duration-derived allocations, and makes sustained downloads and unlock probes cancellation-aware.
- Temporary Mihomo children receive parent-death protection, benchmark workers are cancelled and joined during shutdown, and the watchdog cannot indefinitely block service cleanup.

## Verification

Passed before release: formatting, all-target/all-feature check and tests, router-only and all-feature Clippy with warnings denied, frontend and installer contracts, the fixture-backed browser suite, and `git diff --check`.

## Live deployment evidence

The final hash-verified artifact was deployed transactionally to Keenetic Giga KN-1012 with the complete rollback set retained at `/opt/etc/hincyray/rollback-v1.3.5-20260915-095423`. The daemon reported v1.3.5 with the existing active profile preserved, Mihomo and firewall running, the canonical `proxy` fallback group alive on `proxy-active`, DNS redirect active, TCP REDIRECT on port 10810, and UDP TPROXY on port 10811. The bounded router E2E suite passed.

After deployment, HincyRay used two threads and approximately 14.8 MiB RSS. `/api/status` was 828 bytes instead of the previous 64,749-byte routing-bearing response, `/api/logs` returned a 28,706-byte bounded tail, and `/api/routing` omitted both internal probe timestamp caches.
