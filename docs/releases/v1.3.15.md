# HincyRay v1.3.15

Date: `2026-09-20`.

This release changes generated VPN routing from fail-open to fail-closed after a live direct-WAN exposure was captured during brief active-profile health flaps. GitHub commit, push, and release remain pending and unauthorized.

## Incident

- A LAN request through HincyRay used the expected Swedish VPN egress while a separately bound `qmi_br0` request showed the Russian mobile-WAN egress.
- The daemon log repeatedly recorded `proxy unreachable, mihomo fallback to DIRECT (auto-switch disabled)`, followed by recovery after 95-371 ms. The canonical Mihomo group was `[proxy-active, DIRECT]`, so these brief failures intentionally exposed the WAN address.
- Core, firewall, DNS redirect, TCP REDIRECT, UDP TPROXY, policy table 111, and all three LTE carriers were present. This was not an iptables bypass or a B7-only radio event.
- Private incident evidence is retained under `/tmp/opencode/leak-live-20260920-112724`.

## Fix

- The canonical group is `[REJECT, proxy-active]`. Mihomo skips unhealthy REJECT while VPN is healthy. When every member is unhealthy, Mihomo selects the first member, so requests are rejected locally rather than sent directly or repeatedly dialed through a dead upstream.
- Pinned server groups are `[REJECT, pinned-outbound, proxy-active]`; Parovozik VPN is `[REJECT, proxy-active, ...]`. An exact route to the current active server resolves through canonical `proxy`, not raw `proxy-active`.
- The watchdog requires `now=proxy-active` and raw `proxy-active.alive=true`; aggregate `proxy.alive` remains schema-validated but cannot prevent recovery after an unrelated aggregate delay result.
- Default delay diagnostics probe raw `proxy-active`. The Web UI renders any REJECT chain as rejected and treats missing/non-boolean `alive` as unhealthy.
- Explicit DIRECT rules and configured direct routing remain intentionally direct. The fail-closed guarantee applies to generated VPN-target groups, not to user-selected DIRECT, direct GeoBase/RU routes, configured port bypasses, or local/private firewall bypass destinations.

## Runtime Proof

- Immediate containment changed the live canonical group before the release build. The first containment backup is `/opt/etc/hincyray/mihomo-config.yaml.pre-fail-closed-20260920-113206`; the corrected REJECT-first backup is `/opt/etc/hincyray/mihomo-config.yaml.pre-reject-first-20260920-115108`.
- Production runtime showed `REJECT alive=false`, `proxy-active alive=true`, group `now=proxy-active`, and Swedish egress `95.111.205.44`.
- An isolated temporary Mihomo using the installed v1.19.29, separate ports 11980/19090, and dead upstream produced group `all=[REJECT,dead-proxy]`, `now=REJECT`; its SOCKS request failed with an empty body and no public IP. The temporary child and files were reaped and removed.
