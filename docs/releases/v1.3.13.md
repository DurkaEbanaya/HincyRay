## Policy Scope

- Ordinary all/global, subscription, group, single, favorite, selected, and explicit Dead Servers Check Services actions use `availability_full` with the same shared GUI service-prefix and fail-fast choices.
- Optional strict `service_checks` requires both `required_services` and boolean `fail_fast`; unknown fields/invalid values reject, and it is mutually exclusive with `search`. API prefixes are `youtube` (YT), `telegram` (YT+TG), and `ai`/`all` (YT+TG+AI), not arbitrary standalone combinations. Both availability methods accept the policy; the ordinary GUI uses `availability_full`.
- Missing/null policy preserves shipped method defaults, including v1.3.12 full/all continued checking for `availability_full`. Deliberately selected fail-fast can skip later selected services after YT/TG failure; unrequested/skipped zero-attempt resources are not failures.
- All and fail-fast are selectable in both ordinary and advanced modes. Ordinary checks process their selected scope without `search` or generic preflight; only the separate explicit advanced global Find N action has the candidate target/preflight/early-stop policy. Saved native Quick/Full compatibility stays separate.

Current parameters: [`../service-check-parameters.md`](../service-check-parameters.md).

## Worker and Probe Bounds

Ordinary explicit-policy requests must admit exactly `min(requested workers, candidates)` or reject with HTTP 503 before reservation, without replacing an existing job. They may not silently reduce workers or bypass memory limits. One candidate gets one worker, not duplicate tests. Startup estimates remain an 80 MiB router reserve plus 48 MiB per worker; four require an estimated 272 MiB available, and unknown/zero budgets reject. This is not a continuous reserve or aggregate decoder-memory guarantee.

Legacy/adaptive requests retain bounded memory admission; Find N also retains remaining-target limits. A requested four-worker search with target one does not imply four simultaneously admitted candidates.

Contract-1 channel/thumbnail probes are candidate-local and no longer acquire the global native YouTube mutex. Each worker owns a private temporary core/config/captures, bounded HTML/image/decoder work, and cancellation/reaping guards. Native contract-7 Innertube playback and the shared Telegram SQLite session remain serialized. Per worker: HTML 2 MiB/20 seconds, each image 128 KiB/8 seconds, HTTPS `i.ytimg.com:443` without redirects, dimensions at most 1024 pixels, decoder allocation at most 16 MiB. These are per-worker limits, not proof of peak aggregate memory use.

YouTube still requires public MrBeast identity and three distinct actually decoded previews. No native YouTube video, authentication/cookie/session import, JavaScript/yt-dlp runtime, or protocol/SNI/certificate/timeout workaround is introduced by this method. Preview resources cannot become native playback, generic EWMA health, or automatic promotion/Dead Servers/AutoSelect evidence.
